Lectures 01 – 04: Linked Lists and Foundations
Lec 01 Introduction to Data Structures + Arrays + List ▼

What is a Data Structure?

A data structure is a way of organizing data inside a computer so that programs can work faster and use less memory. When data becomes large, choosing the right data structure becomes critical — it can make a program 100x faster without buying new hardware.

Yaad rakho: faster CPU khareedna solution nahi hota — sahi data structure use karna hota hai.

How to Select a Data Structure?

First, analyze the problem — how much data is there, and what operations are needed (insert, delete, search)? Then pick the structure that best fits those operations. Every data structure has three costs: space (memory), time (speed), and programming effort.

3 costs yaad karo: space, time, aur effort — koi bhi structure sab mein perfect nahi hota.

Array

An array stores elements in a continuous block of memory with fixed size. You can access any element instantly using its index. The problem: inserting or deleting in the middle requires shifting all other elements, which is slow.

int x[6]; for(j = 0; j < 6; j++) x[j] = 2 * j; // stores: 0,2,4,6,8,10
Array = random access fast (O1), lekin insertion/deletion slow kyunki shifting karni padti hai.

List Data Structure

A list does not require continuous memory. Elements are linked together using pointers. Unlike arrays, you can grow or shrink it at runtime, and inserting/deleting is much easier.

List = flexible size, array = fixed size — yeh fundamental farq hai.

Lec 02 Linked List Methods: add, next, remove, find ▼

add() Method

Inserts a new element at the current position in the list. A new node is created, its pointer is set to the next existing node, and the previous node's pointer is updated to point to the new node.

Pointer update ki sequence important hai — pehle naya node ka next set karo, phir previous ka next update karo.

next() Method

Moves the current pointer to the next node. Used to traverse the list from one node to the next.

next() = ek qadam aage badho list mein.

remove() Method

Removes the current node from the list. The previous node's pointer is updated to skip over the removed node and point directly to the node after it. If memory was dynamically allocated, it must be freed.

Remove karte waqt chain tutne se bachao — pehle pointers adjust karo, phir node delete karo.

find() Method

Searches the entire list for a specific value by checking each node one by one from the beginning until the value is found or the list ends.

find() worst case = puri list check karni padti hai — O(n) time complexity.
linked listmethodstraversal
Lec 03 Linked List in Memory + C++ Implementation ▼

How Linked List Lives in Memory

In an array, all elements sit in one continuous block of memory. In a linked list, each node can be stored anywhere in memory — they are connected only by pointers. This is why a linked list does not need a fixed size declared upfront.

Sochlo: Array = ghar row mein. Linked list = ghar alag alag jagah, pointers chitthi ki tarah connect karte hain.

Node Structure in C++

Each node contains two things: the actual data, and a pointer to the next node. This is how nodes are chained together to form a list.

struct Node { int data; // the value stored Node* next; // pointer to next node };
Har node = data + next pointer. Yeh do cheezein har linked list node mein zaroor hoti hain.

Linked List Operations

For inserting at the beginning, end, or middle — you always need to carefully update pointers in the right order. One wrong pointer assignment can break the entire chain and lose access to parts of the list.

Pointer update ka golden rule: pehle naye node ka next lagao, phir purane node ka next badlo — kabhi ulta mat karo.
memorynodespointersC++
Lec 04 Doubly Linked List + Circular List + Josephus Problem ▼

Doubly Linked List

Each node has two pointers: one pointing to the next node and one pointing to the previous node. This allows traversal in both directions — forward and backward. The trade-off is that each node uses more memory.

Doubly = do pointers per node. Faida: pichhe bhi ja sako. Nuksan: zyada memory.

Array vs Linked List Analysis

Array gives O(1) random access (jump directly to any index). Linked list requires O(n) to reach the nth element (must walk through each node). However, linked list insertion and deletion are faster once you have the pointer to the right location.

Array = fast access, slow insert/delete. Linked list = slow access, fast insert/delete. Trade-off samajhna zaruri hai.

Circular Linked List

The last node's next pointer points back to the first node instead of NULL. This creates a circular loop — you can keep traversing indefinitely.

Circular list mein koi NULL nahi hota last node par — yeh ek loop hai.

Josephus Problem

10 people stand in a circle. Every 3rd person is eliminated. A circular linked list perfectly models this — keep removing every 3rd node until only one remains. That one is the leader.

Josephus = circular linked list ka best real-world example — MCQ mein agar poocha toh yahi answer hai.

Lectures 05 – 09: Stack, ADT, Expressions
Lec 05 Abstract Data Type (ADT) + Stack + Stack using Array ▼

Abstract Data Type (ADT)

An ADT defines what operations a data structure supports, but hides how those operations are implemented internally. The user only sees the interface — not the internal code. This is the same concept as C++ classes with private and public members.

ADT = sirf interface dikhao, implementation chhupao — jaise car chalana seekhne ke liye engine samajhna zaruri nahi.

Stack — What Is It?

A stack is a LIFO structure — Last In, First Out. The last element you put in is the first one you get out. Think of a stack of plates: you always pick the top one first.

LIFO = Last In, First Out. Two main operations: PUSH (add to top) and POP (remove from top). Everything happens at the top only.

Stack Implementation using Array

Use an array and a variable called "top" to track where the stack ends. Push: increment top, then store the element. Pop: read the element at top, then decrement top.

Push: top++; arr[top] = value; Pop: value = arr[top]; top--;
Stack overflow = array full ho gaya aur push kiya. Stack underflow = stack empty tha aur pop kiya — dono error cases hain.
ADTstackLIFOpush/pop
Lec 06 Stack with Linked List + Infix to Postfix Conversion ▼

Stack using Linked List

Instead of an array, you can build a stack using a linked list. Advantage: no fixed size limit — the stack grows dynamically. Disadvantage: each node uses a little extra memory for the pointer.

Array stack = fast, fixed size. Linked list stack = flexible size, thodi zyada memory. Dono valid implementations hain.

Infix, Postfix, Prefix

Infix: operator is between operands — how humans write: A+B. Postfix: operator comes after operands — AB+. Prefix: operator comes before — +AB. Computers prefer postfix because it removes the need for parentheses and precedence rules during evaluation.

Infix → Postfix A+B → AB+ A+B*C → ABC*+ (A+B)*C → AB+C*
Computer ke liye postfix easy hai — parentheses ki zarurat nahi, stack se seedha evaluate ho jaata hai.

Operator Precedence

Multiplication and division have higher precedence than addition and subtraction. During infix to postfix conversion, this rule determines when to pop operators from the stack to the output.

Conversion rule: operand aaya = output mein likho. Operator aaya = pehle same/higher precedence wale stack se output mein daalo, phir naya push karo.
infixpostfixprecedence
Lec 07 Evaluating Postfix Expressions + Full Infix to Postfix Algorithm ▼

Evaluating a Postfix Expression

Read the expression left to right. If you see a number, push it onto the stack. If you see an operator, pop two numbers, apply the operator, and push the result back. The final answer is the last item on the stack.

Expression: 4 3 5 * + Push 4 → Stack: [4] Push 3 → Stack: [4, 3] Push 5 → Stack: [4, 3, 5] * → pop 5,3 → 3*5=15 → Stack: [4, 15] + → pop 15,4 → 4+15=19 → Answer: 19
Pop karne ki order important: pehle wala = right operand, doosra = left operand. a op b hoga, ulta mat karna.

Infix to Postfix — Full Algorithm

1. Operand (number/letter): write directly to output. 2. '(' : push onto stack. 3. ')' : pop from stack to output until '(' is found; discard both parentheses. 4. Operator: pop operators of equal or higher precedence from stack to output, then push the new operator. 5. End of input: pop all remaining stack items to output.

Parentheses khud output mein nahi aate — sirf andar wale operators ko force karte hain pehle evaluate hone ke liye.
postfix evaluationstack algorithm
Lec 08 C++ Templates + Stack Implementation + Function Call Stack ▼

C++ Templates

A template lets you write one generic class or function that works for any data type. Instead of writing a separate Stack class for int, float, and string, you write one template and the compiler generates the specific version for you.

template <class T> class Stack { T data[100]; int top; // works for int, float, string, etc. };
Template = ek mold, alag alag materials (data types) se same shape bana sakte ho — baar baar likhna nahi padta.

Function Call Stack

Every time a function is called, the computer pushes a "stack frame" (also called activation record) onto the call stack. This frame holds the function's parameters, local variables, and return address. When the function finishes, the frame is popped and control returns to the caller.

Recursion isi mechanism par kaam karta hai — har recursive call ek naya frame push karta hai. Bahut deep recursion = stack overflow.

Lec 09 Memory Organization + Stack Layout During Function Calls ▼

Memory Organization

When a program runs, the OS divides memory into four areas: Code Section (the compiled program instructions), Static Data (global variables), Stack (for function calls), and Heap (for dynamic memory allocation using new/malloc).

Stack = function calls manage karta hai. Heap = new/malloc se runtime mein memory milti hai. Dono bilkul alag cheezein hain.

Stack Layout During a Function Call

When function A calls function B, a new activation record is pushed onto the stack. It contains B's parameters, B's local variables, and the return address (so the program knows where to go after B finishes). When B returns, that record is popped off.

Activation record = function ka sara saman (parameters + local vars + return address). Function khatam = saman uthao.

Lectures 10 – 13: Queue, Priority Queue, Binary Trees
Lec 10 Queue — Operations, Array Implementation, Use Cases ▼

What is a Queue?

A queue is a FIFO structure — First In, First Out. The first element added is the first one removed. Like a line at a counter: whoever arrives first gets served first.

Stack = LIFO. Queue = FIFO. These are opposite — do not mix them up in MCQs.

Queue Operations

Enqueue: add an element to the rear of the queue. Dequeue: remove an element from the front. Front: peek at the front element. IsEmpty: check if the queue has any elements.

Queue = ek taraf se andar aao (rear), doosri taraf se niklain (front) — one-way street.

Queue using Array + Circular Queue

Use two pointers: front and rear. Enqueue increments rear and adds; dequeue reads from front and increments front. Problem: as elements are removed, space at the beginning of the array is wasted. Solution: circular array — when rear hits the end, wrap it back to index 0.

rear = (rear + 1) % arraySize; // circular wrap
Circular queue trick = rear = (rear+1) % size. Isse starting space waste nahi hota aur array effectively reuse hoti hai.
queueFIFOenqueuedequeuecircular array
Lec 11 Priority Queue + Binary Tree Basics + Terminology ▼

Priority Queue

A variation of a queue where each element has a priority value. When dequeuing, the element with the highest priority is removed first — regardless of when it was added. It is not strictly FIFO.

Hospital emergency = priority queue. Serious patient pehle serve hoga chahe baad mein aaya ho.

Tree Data Structure

A tree is a hierarchical data structure with one root node at the top. Branches extend downward to child nodes. It looks like an upside-down tree. Unlike linked lists (linear), trees are non-linear.

Binary Tree

A tree where every node has at most 2 children: a left child and a right child. "Binary" means two.

Key Terminology

Root: the topmost node (no parent). Leaf: a node with no children. Parent/Child: connected nodes above/below. Height: number of edges from root to the deepest leaf. Level: root is at level 0; its children at level 1, and so on. Strictly Binary Tree: every node has exactly 0 or 2 children — never 1. Complete Binary Tree: all levels are fully filled except possibly the last, which is filled from the left.

Strictly binary = 0 ya 2 children, kabhi 1 nahi. Complete binary = sab leaves same level par (ya ek level kam, left se fill). Dono alag definitions hain.
priority queuebinary treerootleafheight
Lec 12 BST Rule + Insert Operation + Searching for Duplicates ▼

Binary Search Tree (BST) Rule

In a BST, for every node: all values in its left subtree are smaller, and all values in its right subtree are larger. This rule applies to every node in the entire tree.

14 / \ 4 15 / \ \ 3 9 18 Left of 14 = {4,3,9} all < 14. Right = {15,18} all > 14.
BST rule = left chhota, right bara. Yeh rule har node par apply hota hai, sirf root par nahi.

Insert in BST

Start from root. If the new value is smaller, go left; if larger, go right. Repeat at each node until you reach a NULL spot — insert there.

BST insert = compare and go left/right until NULL milta hai — wahan naya node lagao.

Searching in BST

Same logic as insert — compare at each node and go left or right. At each step, half the remaining tree is eliminated. Average time: O(log n). Worst case (a skewed tree): O(n).

Balanced BST = O(log n) search. 1 million elements mein sirf 20 comparisons. Skewed BST = O(n) — basically a linked list.
BSTinsertsearchO(log n)
Lec 13 Tree Traversals — Inorder, Preorder, Postorder ▼

Three Traversal Methods

Inorder (Left → Root → Right): visiting in this order on a BST always gives sorted output. Preorder (Root → Left → Right): visits root first, useful for copying a tree. Postorder (Left → Right → Root): visits root last, useful for deleting a tree or evaluating expression trees.

Tree: 4 / \ 2 6 / \ 1 3 Inorder: 1, 2, 3, 4, 6 ← sorted! Preorder: 4, 2, 1, 3, 6 Postorder: 1, 3, 2, 6, 4
Inorder of BST = always sorted sequence — yeh ek guaranteed property hai, exam mein zaroor aayegi.

Recursive Implementation

All three traversals are naturally recursive. The code is very short — just call the same function on the left subtree, then right subtree, with the root visit in the appropriate order.

void inorder(Node* n) { if(n == NULL) return; inorder(n->left); // Left cout << n->data; // Root inorder(n->right); // Right }
Bas order yaad karo: In = L-Root-R, Pre = Root-L-R, Post = L-R-Root. Baaki code same rahega.

Lectures 14 – 18: Traversal Depth, BST Delete, Reference Variables
Lec 14 Recursive Calls + Non-Recursive Traversal + Traversal Trace ▼

How Recursive Calls Work Internally

When a function calls itself, a new stack frame is pushed onto the call stack containing the current parameters and local variables. When the recursive call returns, that frame is popped and execution continues from where it left off. This is exactly the same mechanism as normal function calls.

Recursion samajhna easy hai: base case = kab rokna hai, recursive case = khud ko call karo. Stack automatically sab track karta hai.

Preorder and Inorder Recursion Trace

You can trace the exact sequence of stack pushes and pops to understand what happens step by step during a recursive traversal. Each recursive call saves its state on the stack and resumes exactly where it stopped when the child call returns.

Traversal trace mein: jab function call hoti hai, stack par push; jab return hoti hai, pop. Yeh trace exam mein draw karna aa sakta hai.

Non-Recursive Traversal

You can implement any tree traversal without recursion by using an explicit stack. Instead of relying on the call stack, you manually push and pop nodes. This gives you more control and can be more memory-efficient for very deep trees.

Non-recursive = apna khud ka stack use karo instead of recursion. Same result, different implementation.
recursionstack framesnon-recursivetraversal trace
Lec 15 Level-Order Traversal + Strings in BST + Deleting a Node (3 Cases) ▼

Level-Order Traversal

Visit the tree level by level — first the root, then all nodes at depth 1, then all nodes at depth 2, and so on. This is implemented using a Queue (not a stack). Enqueue the root, then for each dequeued node, enqueue its children.

Level 0: 14 Level 1: 4 15 Level 2: 3 9 18 Level 3: 7 16 20
Level-order = Queue use hoti hai. Normal traversals (in/pre/post) = Stack (recursion). Yeh farq important hai — MCQ mein aata hai.

BST with Strings

BSTs are not limited to numbers. Strings work the same way — comparison is alphabetical. "apple" < "banana" so apple goes in the left subtree. All BST rules apply identically.

String BST = same rules, bas comparison alphabetical hoti hai numbers ki jagah.

Deleting a Node from BST — 3 Cases

Case 1 — Leaf node (no children): simply remove it and set the parent's pointer to NULL. Case 2 — One child: remove the node and connect the parent directly to that one child. Case 3 — Two children (hardest): find the inorder successor (the smallest node in the right subtree — the leftmost node there). Copy its value to the node being deleted, then delete the inorder successor (which is always a case 1 or case 2 deletion).

Case 3 shortcut: inorder successor = right subtree ka sabse left (chhota) node. Uski value copy karo, phir use delete karo.
level orderqueueBST deleteinorder successor
Lec 16 BST Deletion C++ Code + BST Class ▼

C++ Code for BST Remove

The remove function first searches for the target node. Then it checks which case applies (0, 1, or 2 children) and adjusts pointers accordingly. If the node was dynamically allocated, memory is freed using delete.

Guaranteed property: inorder successor ka left child kabhi nahi hota — agar hota toh woh leftmost nahi hota. Yeh deletion simplify karta hai.

BST as a C++ Class

The entire BST is wrapped inside a class. Public interface: insert(), remove(), find(). Private: the root pointer and helper (recursive) functions. This is encapsulation — the user of the class does not need to know the internal tree structure.

Class = ADT ka C++ implementation. Public = jo user dekhta hai. Private = andar ki machinery — chhupao isay.

Lec 17 Reference Variables + & Operator + Call by Value/Reference/Pointer ▼

What is a Reference Variable?

A reference variable is an alias — another name for an existing variable. Both names refer to the same memory location. Changing one changes the other automatically.

int x = 10; int& ref = x; // ref is another name for x ref = 20; // x is now also 20
& ka teen jagah alag matlab: (1) &x = address of x, (2) int& r = x = reference variable, (3) a&b = bitwise AND. Context se pehchano.

Call by Value vs Reference vs Pointer

Call by Value: a copy is passed; original is not changed. Call by Reference: the original variable is passed directly; changes inside the function affect the original. Call by Pointer: a pointer to the variable is passed; you can change the original by dereferencing the pointer.

Function signature mein insert(const EType& x): const = change nahi hoga, & = copy nahi bani (efficient for large objects). Dono ek saath use hote hain.

Lec 18 const Keyword + Transient Objects + Tips ▼

const Keyword

const locks a variable's value — it cannot be changed after initialization. In function parameters, using const tells the compiler and the reader that this function will not modify the passed value. The compiler enforces this.

void insert(const int& x) { // x cannot be modified here // but no copy is made (passed by reference) }
const + reference = best combination: no copy (fast) + no accidental modification (safe). Isliye C++ mein BST methods mein yahi pattern milta hai.

Transient Objects and Dangling References

Local variables are created on the call stack and destroyed when the function returns. If you store a reference to a local variable inside a data structure, and the function returns, that reference now points to destroyed (invalid) memory. This is called a dangling reference and is a serious bug.

Kabhi bhi local variable ka reference/pointer data structure mein store mat karo — function return hone ke baad woh memory invalid ho jaati hai.

Stack Concept Across Languages

The concept of function calls using a stack is universal — it works the same in Java, FORTRAN, Pascal, and C++. Only the syntax differs. Java passes native types by value and objects by reference. FORTRAN passes everything by reference.

Stack mechanism sab languages mein same hai — yeh hardware level concept hai, kisi ek language ka nahi.

Stack = LIFO, Queue = FIFO — mix mat karna MCQs mein, yeh sabse common mistake hai.
Inorder traversal of BST = always sorted output. Yeh guaranteed property hai.
Circular linked list = last node ka next, first node par point karta hai (NULL nahi).
Level-order traversal = Queue use karta hai. Baaki traversals (in/pre/post) = Stack.
BST delete case 3 = inorder successor se replace karo — right subtree ka leftmost node.
Postfix evaluate: operator aaya toh 2 numbers pop karo, operate karo, result push karo.
const& parameter = fast (no copy) + safe (no modification). Best practice in C++.
Array vs Linked List: Array = fast access O(1). Linked list = fast insert/delete, slow access O(n).
